# Spec Delta

## MODIFIED Requirements

### Requirement: Index-backed room queries

Edition: CE. Every query of this capability SHALL run on an index of the shared contract
(`dashboard-ce/typings/contract/indexes.ts`), or on `_id` for the hourly rollups the long-range summary reads: no
winning plan contains a `COLLSCAN`, and `totalDocsExamined` is bounded
by the page size plus the documented residual filters for the index-ordered pages and by the rooms created in the range
for the ranked sorts and for the name searches, which may sort in memory.

#### Scenario: Explain plans on the generated database

- **GIVEN** a database generated by the data generator at scenario M
- **WHEN** the list (every filter combination and sort) and summary queries are explained
- **THEN** each winning plan uses an index of the shared contract and none contains `COLLSCAN`

#### Scenario: Ranked sorts over 7 days

- **GIVEN** a database generated at scenario M for 7 days
- **WHEN** the list is explained with each ranked sort key, with and without `status`, `q`, `mediaNode` and `features`
- **THEN** each plan scans the range index of its filters (`createdAt_id`, `status_createdAt_id`,
  `nameLower_createdAt`, `mediaNode_status_createdAt_id` or the feature indexes), `totalDocsExamined` is at most the rooms
  created in the range, and the p95 of a page is within 300 ms

#### Scenario: Name prefix within one node

- **WHEN** the list with `q` set to a prefix of one room's name and `mediaNode` is explained
- **THEN** the plan uses `nameLower_createdAt` with `mediaNode` as a residual filter

## ADDED Requirements

### Requirement: Room list plans

Edition: CE. Without `q`, the rooms list SHALL run its page, ranked sorts and `total` on
`mediaNode_status_createdAt_id` with `mediaNode`, else on the partial index of the feature with one feature, else on
`status_createdAt_id` with a status. Several features without `mediaNode`, and `q`, SHALL leave the index to the query planner, except
that `q` with a status SHALL run its ranked sorts and `total` on `mediaNode_status_createdAt_id` with `mediaNode` and
on `status_createdAt_id` otherwise.

#### Scenario: Hinted room filters

- **WHEN** the list is explained with `status=closed`, with `mediaNode` and with `features=egress`, for the page,
  `total` and each ranked sort
- **THEN** every plan of a filter uses its index (`status_createdAt_id`, `mediaNode_status_createdAt_id`,
  `status_createdAt_id_egress`), never `status_endedAt_id`, and examines at most the rooms of that filter created in
  the range

#### Scenario: Several features

- **WHEN** the list with `features=egress,agent` is requested and explained
- **THEN** the page uses `status_createdAt_id_egress` and `status_createdAt_id_agent` with no in-memory sort, and
  `items` and `total` hold every room created in the range that used egress or an agent

#### Scenario: Selective room name prefix

- **WHEN** the list is explained with `q` set to a prefix of one room's name, for the page, `total` and a ranked sort
- **THEN** each plan uses `nameLower_createdAt` and examines at most the rooms of that prefix created in the range

#### Scenario: Broad room name prefix

- **GIVEN** a generated database whose room names all start with `room-`
- **WHEN** the list is explained with `q=room`, alone and with `status=closed`, for the page, `total` and each ranked
  sort
- **THEN** the page uses a range index with no in-memory sort and examines at most two pages, the ranked sorts and
  `total` with `status=closed` use `status_createdAt_id`, and no plan uses `status_endedAt_id` or examines more than
  the rooms created in the range
